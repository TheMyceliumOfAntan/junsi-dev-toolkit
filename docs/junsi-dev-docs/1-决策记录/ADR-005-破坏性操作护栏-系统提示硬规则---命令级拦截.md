# ADR-005：破坏性操作护栏：系统提示硬规则 + 命令级拦截

| 属性 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-11-06 |
| 决策者 | AI Agent |

## 背景

一次 AI 会话清空/删除了 $HOME 下的工具目录（~/.bun、~/.cargo/bin、pnpm 全局目录），导致 bun/cargo/vercel/wrangler 等命令全部失效。现有 ai-compliance 只讲文件编辑编码，没有任何删除/覆盖护栏，且提示词约束对高危命令不够硬。

## 决策

双层护栏：(1) 插件每轮把 SAFETY_RULES 注入 system（system 不持久，必须每轮注入；压缩钩子也注入），硬性禁止对 $HOME/~/%USERPROFILE%/盘根及通配符递归删除或覆盖，禁止删除 .ssh/.config/.cargo/.rustup/.bun/.local/AppData/.git，删除前必须打印解析后的绝对路径；(2) 注册 tool.execute.before 钩子，对 bash/shell 类工具的命令做正则检测，命中主目录/受保护目录的递归删除直接抛错拦截，项目内 dist/node_modules 清理放行。同时在 shared/ai-compliance.md 与 ~/.config/opencode/AGENTS.md 各写一份同样规则（机器级双保险）。

(3) 2026-11-08 事故（`$home = ...` 赋值失败 → `Split-Path $home` = `C:\Users` → 整个用户目录被递归删除）后加固：

- **删除目标只接受字面路径**：变量、`Split-Path`、`Join-Path`、`Resolve-Path`、`..` 算出的目标一律拦截 —— 真实路径在运行前不可见，文本匹配只能靠猜。只看删除动词之后的目标 token，同语句里的其它表达式不误伤。
- **变量名大小写不敏感**：`$home` = `$HOME` = `$Home`，是只读自动变量，赋值静默失败、变量保持原值；`$env:TEMP` 例外放行，裸 `$temp` 不放行。
- **裸写的盘符 + Users** 纳入主目录判定（`C:\Users`、`C:\Users\`、`C:\Users\foo\bar`）。
- **`-WhatIf` 演练放行**；行尾注释不参与判定。
- **注册失败不再静默**：`tool.execute.before` 注册失败时，注入文本末尾追加「命令级护栏未注册成功」告警。
- **同一护栏兼管文件写入**：拦截 PowerShell `Set-Content`/`Out-File`/`Add-Content` 写源码与文档（Windows PowerShell 5.1 默认 ANSI/GBK，UTF-8 中文会乱码），要求改用 `edit`/`write` 工具。

## 备选方案

### 方案 只写进 AGENTS.md
- 优点：零代码
- 缺点：依赖宿主是否读取；无命令级拦截
- 为何不选：保留，但作为补充

### 方案 只做命令级拦截
- 优点：最硬
- 缺点：钩子名在 V2 运行时可能不支持，且模型改写命令即可绕过
- 为何不选：保留，但必须配提示词

### 方案 删除前强制 question 确认
- 优点：最安全
- 缺点：每次清理都打断，噪音大
- 为何不选：仅对卸载/重装全局包保留 question
